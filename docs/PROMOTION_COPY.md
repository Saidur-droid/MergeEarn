### Post

I built **MergeEarn** for the Nimiq Mini Apps Competition.

Open-source bounties often depend on screenshots, manual status updates, and payout spreadsheets. MergeEarn connects the two sources of truth directly:

- **GitHub proves the work** — repository permissions, source issue, expected base branch and merged PR state are verified server-side.
- **Nimiq proves the money** — funding and payout are signed through Nimiq Pay and independently verified before the bounty can become `FUNDED` or `PAID`.

The flow is simple:

**Issue → Bounty → Fund → Claim → PR → Merge → Verify → Approve → Pay**

The maintainer selects a real GitHub issue and funds a NIM reward. A contributor claims it, submits the actual PR, and only becomes payable after that PR is merged and verified. The payout then goes to the contributor through Nimiq.

## LinkedIn post

I’ve been building **MergeEarn**, a Nimiq Mini App that turns real GitHub issues into funded, verifiable bounties.

The idea is to remove a weak point in many bounty workflows: the app should not trust a screenshot saying that work was merged, and it should not trust the browser saying that a payment succeeded.

MergeEarn treats **GitHub as the source of truth for work** and **Nimiq as the source of truth for money**. Maintainers can select a real issue and fund a NIM reward. Contributors claim the bounty and submit the real pull request. The backend verifies the expected repository, base branch and merged state before approval. Funding and payout transactions are independently checked before the bounty moves to its money-sensitive states.

Core flow: **Issue → Fund → Claim → PR → Merge → Verify → Approve → Pay**
